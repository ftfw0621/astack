### Investigation

**You own the answer. Plan, route, write.** Read-only. The output is a cited explanation or a recommendation, never a code change.

1. Route through the `how` skill. For a motivation question ("why was this built this way"), also route through the `why` skill when it is installed, otherwise read `git log -p` and the linked PRs yourself and label what you infer.
2. Produce the `how`-shaped output (Overview, Key concepts, How it works, Where things live, Gotchas), or a recommendation with a tradeoffs table when the request is a choice between alternatives.
3. Apply the `unslop` skill to the reply.

No PR, no `architect`, unless the investigation precedes a code change. Then hand back and re-route to Bug fix or Feature.

**Reply:** the investigation output. For "are we sure?", your real judgment with reasons. Push back when the premise is wrong.
